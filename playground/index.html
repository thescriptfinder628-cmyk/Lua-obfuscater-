What this does — and what it cannot do

Any protection you can hand to a runtime can eventually be undone by that same runtime.

It removes the easy wins

No names, no strings, no readable structure, no comments. Grepping for a key, an endpoint or a variable is impossible; following the logic requires following randomly numbered states.

Strings need a runtime decoder

Every encrypted string is decrypted in memory before use, so a memory dump or a traced string.char can recover them. The per-string VM makes that a per-string job, not a single script.

Bytecode is a different problem

If you also ship luac output, protect that separately — obfuscating the source does not obfuscate its compiled form.

It is not encryption

Nobody needs your key to run the script. Treat this as a very high wall, not a vault: it buys time and deters casual copying, it does not make reverse-engineering theoretically impossible.

Verify before you ship. The verify by running switch executes your script and the obfuscated build and compares their output. If they differ, you get nothing back — a broken build never leaves the page.
